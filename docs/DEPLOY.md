# Развёртывание

Продакшен состоит из трёх контейнеров: `caddy` принимает HTTPS и сам выпускает сертификат, `app` отдаёт фронтенд и API, `db` хранит данные PostgreSQL в томе `learn-data`. Наружу открыт только Caddy.

Все команды ниже выполняются на сервере в папке проекта. Чтобы не повторять длинную команду, один раз задай сокращение в текущей сессии терминала:

```sh
alias learn='docker compose -f compose.yaml -f compose.prod.yaml'
```

## Что нужно заранее

- Сервер с Linux, Docker Engine и плагином Docker Compose v2. Хватит 1 vCPU, 1 ГБ памяти и 10 ГБ диска.
- Домен или поддомен, например `learn.example.com`. A-запись указывает на IP сервера.
- Открытые входящие порты 80 и 443. Они нужны Caddy для сертификата и HTTPS. [Требования Caddy](https://caddyserver.com/docs/automatic-https#overview)
- Бот в Telegram. Токен выдаёт [@BotFather](https://t.me/BotFather) командой `/newbot`.
- Числовой Telegram ID ментора. Напиши своему боту любое сообщение и открой `https://api.telegram.org/bot<токен>/getUpdates`, ID лежит в `message.from.id`. Способ работает, пока у бота нет webhook.

## Первый запуск

1. Получи код и перейди в рабочую ветку.

```sh
git clone https://github.com/EdinstvoAI/Edinstvo-Learn.git
cd Edinstvo-Learn
git checkout dev
```

2. Создай файл с настройками и закрой его от других пользователей сервера.

```sh
cp .env.example .env
chmod 600 .env
```

3. Сгенерируй два разных секрета. Команду нужно выполнить дважды.

```sh
openssl rand -hex 32
```

4. Заполни `.env`.

| Переменная | Значение |
|---|---|
| `PUBLIC_ORIGIN` | Адрес приложения, например `https://learn.example.com`. Только `https://`, без пути и без `/` в конце. |
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather. |
| `TELEGRAM_MENTOR_ID` | Числовой Telegram ID ментора. |
| `POSTGRES_PASSWORD` | Первый секрет. После первого запуска не меняй: база запоминает пароль при создании тома. |
| `ACCESS_CODE_SECRET` | Второй секрет. Из него считается суточный код доступа. |
| `LOCAL_SETUP_TOKEN` | Оставь пустым. Локальный вход в продакшене отключён. |
| `MENTOR_EMAIL`, `MENTOR_PASSWORD_HASH`, `MENTOR_PIN_HASH` | Необязательно. Вход ментора из браузера, см. раздел ниже. |

5. Собери и запусти контейнеры. Флаг `--wait` дожидается, пока база и приложение пройдут проверку здоровья.

```sh
learn up -d --build --wait
```

6. Проверь результат.

```sh
learn ps
```

```sh
curl -s https://learn.example.com/api/state
```

Все три контейнера должны быть в состоянии `running`, у `db` и `app` статус `healthy`. Запрос возвращает JSON, в котором есть `"telegram":true`. Первый сертификат Caddy получает до минуты.

7. Подключи приложение к боту. В BotFather: `/mybots` → бот → `Bot Settings` → `Menu Button` → укажи адрес из `PUBLIC_ORIGIN`. [Настройка кнопки меню](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button)
8. Открой бота своим аккаунтом и нажми кнопку меню. Откроется список учеников. В «Моём кабинете» виден шестизначный код.
9. Менти открывает того же бота и вводит код. Код меняется в полночь по Волгограду и нужен один раз, при первой активации. Затем менти один раз проходит входной тест.

## Вход ментора из браузера

Без этих переменных ментор входит только через Telegram. Чтобы открывать кабинет с компьютера:

1. На машине с Node.js 22 или новее дважды запусти команду в папке проекта: для пароля и для PIN из 4–8 цифр. Значение вводится с клавиатуры, команда печатает хеш.

```sh
npm run mentor:hash
```

2. Запиши в `.env` почту в `MENTOR_EMAIL` и два хеша в `MENTOR_PASSWORD_HASH` и `MENTOR_PIN_HASH`. Сам пароль и PIN в файл не попадают.
3. Примени настройки командой `learn up -d --wait`.
4. Открой адрес приложения в браузере, удерживай логотип 10 секунд, введи почту и пароль, затем PIN.

После пяти неверных попыток вход закрывается на 10 минут. Перезапуск контейнера `app` сбрасывает счётчик.

## Обновление

```sh
git pull
```

```sh
learn up -d --build --wait
```

Схема базы обновляется сама при старте приложения. Данные в томах сохраняются. Перед обновлением сделай резервную копию.

Откат на предыдущую версию: `git log --oneline` покажет коммиты, затем `git checkout <коммит>` и та же команда `up`. Схема только добавляет таблицы и колонки, поэтому старый код работает с новой базой.

## Резервная копия

Копия базы включает аккаунты, задачи, проекты, оценки и фото.

```sh
learn exec -T db pg_dump -U learn -Fc learn > learn-$(date +%F).dump
```

Восстановление заменяет текущие данные содержимым копии. Приложение на это время останавливается.

```sh
learn stop app
```

```sh
learn exec -T db pg_restore -U learn -d learn --clean --if-exists < learn-2026-11-12.dump
```

```sh
learn start app
```

Храни копии вне сервера. Вместе с копией сохрани `.env`: без `ACCESS_CODE_SECRET` изменятся коды доступа, без `POSTGRES_PASSWORD` приложение не подключится к восстановленному тому.

## Остановка

`learn down` останавливает контейнеры и сохраняет данные. `learn down -v` удаляет тома вместе с базой и сертификатами, используй только для полного сброса.

## Если что-то не работает

Логи приложения и Caddy:

```sh
learn logs --tail=80 app caddy
```

| Симптом | Причина и решение |
|---|---|
| `up` сразу падает с `Set ...` | В `.env` не заполнена названная переменная. |
| `app` перезапускается, в логе `Set PUBLIC_ORIGIN to an HTTPS origin` | `PUBLIC_ORIGIN` с путём, со слешем в конце или без `https://`, либо `TELEGRAM_MENTOR_ID` содержит не только цифры. |
| Браузер пишет об ошибке сертификата | DNS ещё не указывает на сервер или закрыты порты 80 и 443. Причина видна в логе `caddy`. |
| В Telegram «У этого аккаунта нет доступа» | Токен бота в `.env` от другого бота, либо часы сервера расходятся с реальным временем больше чем на 10 минут. |
| Ментор видит экран ученика | В `TELEGRAM_MENTOR_ID` чужой ID. Исправь значение и выполни `learn up -d --wait`. |
| «Код не подошёл» | Код вчерашний, он меняется в полночь по Волгограду. После пяти ошибок ввод закрыт на 10 минут. |
| «Сервис временно недоступен» | Приложение не достучалось до базы. Проверь `learn ps` и `learn logs db`. Частая причина — пароль в `.env` изменили после создания тома. |
| После правки `.env` ничего не поменялось | Настройки читаются при создании контейнера. Выполни `learn up -d --wait`. |
