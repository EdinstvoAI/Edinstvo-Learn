# Архитектура

## Направление

Фронтенд Telegram Mini App на Lit, движение на GSAP и Lottie. Node API обслуживает вход, права и данные. Docker Compose запускает общий контейнер фронтенда и API и отдельный контейнер PostgreSQL 17 с постоянным томом.

## Границы функций

- **Вход и права.** У каждого свой аккаунт. Сервер проверяет подпись Telegram и создаёт запись при первом входе. До ввода сегодняшнего кода аккаунт ждёт активации. Код вычисляется на сервере из секрета, идентификатора ментора и даты по Волгограду. Сервер ограничивает неверные попытки.
- **Задачи.** Сервер применяет право на перенос, заданное ментором. Область настройки и историю переносов уточняем в продукте.
- **Профиль.** Настройки слоёв и фото принадлежат менти. Файлы, время и подписи хранятся в PostgreSQL. Фото доступны самому менти и его ментору.
- **Навыки.** Каталог софтов общий, прогресс свой у каждого. Опросник завершает онбординг один раз. Сервер хранит неизменяемый результат по каждому навыку. Оценки ментора храним отдельно с основанием и датой. Они имеют приоритет при отображении. Харды ментор группирует в один или несколько кругов.
- **Проекты.** Ссылка идентифицирует внешний ресурс. Способ подключения доступа, список событий, периодичность и история обновлений открыты. Требования к правам и секретам в [SECURITY.md](SECURITY.md).

Решения об устройстве и их причины записывай в [DECISIONS.md](DECISIONS.md).

## Разработка и первый запуск

Сервер подтверждает сессию по HttpOnly cookie и ограничивает данные привязкой ментора к ученику. Для локального первого входа используется секрет из окружения. Telegram-вход проверяет подписанный `initData` при настроенном боте.

Настройки, навыки и привязки проектов хранятся в записи профиля. Задачи, фото и сессии лежат в отдельных таблицах. Активация, оценки и однократность теста проверяются в транзакции. Для живого запуска нужны HTTPS и параметры Telegram. Трекинг событий GitHub и Figma и покер идут отдельными этапами.

Проект получает постоянный UUID, включая проекты старых аккаунтов. Задача может хранить UUID проекта из того же профиля. API проверяет принадлежность проекта внутри транзакции с блокировкой профиля. Менти может создать задачу или проект у себя и привязать переносимую задачу, права ментора на закреплённые задачи сохраняются. Фото профиля берётся из проверенных данных Telegram, при отсутствии показываются инициалы.

Повышение оценки добавляет событие роста в профиль менти в той же транзакции. Только менти получает свою очередь и подтверждает проигранное событие. Для публичного окружения роль ментора проверяется по Telegram ID из конфигурации. Docker обслуживает сборку и API одним Node-процессом, Caddy завершает HTTPS.

Комментарии хранятся в конкретном проекте. Их создаёт только ментор, привязанный к профилю менти. Задачи сгруппированы на экране проекта по календарным неделям с понедельника по воскресенье.

Telegram username хранится из проверенного входа. Номер появляется после явного подтверждения в Telegram и серверной проверки подписи контакта и его Telegram ID. Номер видят сам менти и его ментор.
