# Ветки, коммиты и релизы

- Работа идёт в `dev`. Первый релиз в `main` появится по отдельному решению Макара. Для агента, который меняет код, выделяй отдельную ветку и worktree.
- В коммит включай конкретные файлы законченной и проверенной задачи. Отделяй изменения документации от кода, когда они имеют самостоятельный смысл.
- Тема и короткое описание коммита на английском. В теме назови изменение, в теле одной-двумя строками скажи, что поменялось. Пример темы: `Build the mentorship prototype`.
- Локальный коммит делай в рамках поручения Макара. Пуш, слияние и релиз делай только по его слову.
- Перед слиянием прогони проверки проекта. Перед релизом подготовь короткие пункты для ручной проверки Макаром.
