# Развёртывание

Продакшен состоит из двух контейнеров: `app` отдаёт фронтенд и API на `127.0.0.1:5188`, `db` хранит данные PostgreSQL в томе `learn-data`. Установленный на сервере Nginx принимает HTTPS и проксирует запросы в приложение.

## Локальная проверка на своём компьютере

Так можно потрогать приложение целиком за пару минут, без сервера, домена и бота. Данные живут только у тебя.

1. Установи [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запусти его. Для юнит-тестов дополнительно нужен [Node.js](https://nodejs.org/) 22 или новее.
2. Скачай проект и перейди в рабочую ветку.

```sh
git clone https://github.com/EdinstvoAI/Edinstvo-Learn.git
cd Edinstvo-Learn
git checkout dev
```

3. Возьми готовый пример настроек. В нём уже заполнены все значения для локального запуска. Вторая команда удаляет локальную базу от прошлых запусков: PostgreSQL помнит пароль, с которым база была создана, и с новым `.env` старая база не откроется. Если запускаешь впервые, команда просто ничего не найдёт.

```sh
cp .env.local.example .env
docker compose down -v
```

4. Собери и запусти. Первая сборка занимает несколько минут.

```sh
docker compose up -d --build --wait
```

5. Войди ментором. Открой в браузере ссылку из файла `.env`:

```text
http://127.0.0.1:5188/#setup=658bf96303360011b3cda74eeda6186ed77b7059493233540eda3993220ae5a4
```

На Mac то же самое делает команда `npm run local:open`. Откроется пустой список учеников. В «Моём кабинете» виден сегодняшний код.

6. Войди учеником в окне инкогнито или в другом браузере: открой `http://127.0.0.1:5188/`. Первая страница — вход: имя и код из «Моего кабинета». Код нужен один раз, при первом входе, дальше вход по имени. В обычном окне вход ученика заменит вход ментора, потому что сессия хранится в cookie браузера.

Пройди тест, создай проект и задачу. В окне ментора обнови список учеников, открой ученика, выставь оценки, добавь круг хардов и комментарий к проекту. Вернись к ученику, и на главной проиграется анимация роста.

7. Скрытый вход ментора: открой `http://127.0.0.1:5188/` в чистом окне, удерживай логотип 10 секунд, введи почту `mentor@local.test`, пароль `learn-local`, затем PIN `1234`.
8. Юнит-тесты запускаются без Docker:

```sh
npm ci
npm test
```

Остановить приложение с сохранением данных: `docker compose down`. Начать с чистой базы: `docker compose down -v`, затем снова шаг 4. После `git pull` пересобери тем же шагом 4.

Локально не работает то, что требует Telegram: вход через бота, аватар и @username, «поделиться номером» и наклон круга от поворота телефона. Наклон видно, если водить мышью по кругу и по карточке профиля.

Если что-то не запускается:

| Симптом | Что сделать |
|---|---|
| В логах `password authentication failed for user "learn"` | База создана с другим паролем. Выполни `docker compose down -v`, затем шаг 4. |
| `port is already allocated` или `Bind for 127.0.0.1:5188 failed` | Порт занят другим запуском. `docker compose ls` покажет запущенные проекты, останови лишний командой `docker compose -p <имя> down -v` и повтори шаг 4. Или поменяй `LEARN_PORT` в `.env` и открывай ссылки с новым портом. |
| `Cannot connect to the Docker daemon` | Docker Desktop не запущен. Открой его и дождись зелёного статуса. |
| Сборка падает на `npm ci` | Нет доступа к npm из Docker, например из-за VPN или прокси. Отключи их на время сборки. |

Значения из `.env.local.example` открыты всем, кто видит репозиторий. Не используй их на сервере.

## Продакшен

Все команды ниже выполняются на сервере в папке проекта. Чтобы не повторять длинную команду, один раз задай сокращение в текущей сессии терминала:

```sh
alias learn='docker compose -f compose.yaml -f compose.prod.yaml'
```

## Что нужно заранее

- Сервер с Linux, Docker Engine и плагином Docker Compose v2. Хватит 1 vCPU, 1 ГБ памяти и 10 ГБ диска.
- Домен или поддомен, например `learn.example.com`. A-запись указывает на IP сервера.
- Nginx с HTTPS-сертификатом для домена. Входящие порты 80 и 443 должны быть открыты.
- Бот в Telegram. Токен выдаёт [@BotFather](https://t.me/BotFather) командой `/newbot`.
- Числовой Telegram ID ментора. Напиши своему боту любое сообщение и открой `https://api.telegram.org/bot<токен>/getUpdates`, ID лежит в `message.from.id`. Способ работает, пока у бота нет webhook.

## Первый запуск

1. Получи код и перейди в рабочую ветку.

```sh
git clone https://github.com/EdinstvoAI/Edinstvo-Learn.git
cd Edinstvo-Learn
git checkout dev
```

2. Создай файл с настройками и закрой его от других пользователей сервера.

```sh
cp .env.example .env
chmod 600 .env
```

3. Сгенерируй два разных секрета. Команду нужно выполнить дважды.

```sh
openssl rand -hex 32
```

4. Заполни `.env`.

| Переменная | Значение |
|---|---|
| `PUBLIC_ORIGIN` | Адрес приложения, например `https://learn.example.com`. Только `https://`, без пути и без `/` в конце. |
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather. |
| `TELEGRAM_MENTOR_ID` | Числовой Telegram ID ментора. |
| `POSTGRES_PASSWORD` | Первый секрет. После первого запуска не меняй: база запоминает пароль при создании тома. |
| `ACCESS_CODE_SECRET` | Второй секрет. Из него считается суточный код доступа. |
| `LOCAL_SETUP_TOKEN` | Оставь пустым. Локальный вход в продакшене отключён. |
| `MENTOR_EMAIL`, `MENTOR_PASSWORD_HASH`, `MENTOR_PIN_HASH` | Необязательно. Вход ментора из браузера, см. раздел ниже. |

5. Собери и запусти контейнеры. Флаг `--wait` дожидается, пока база и приложение пройдут проверку здоровья.

```sh
learn up -d --build --wait
```

6. Добавь виртуальный хост Nginx. Сертификат можно выпустить через Certbot после включения конфига.

```nginx
server {
    listen 80;
    server_name learn.example.com;

    location / {
        proxy_pass http://127.0.0.1:5188;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

```sh
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d learn.example.com
```

Замени `learn.example.com` на домен из `PUBLIC_ORIGIN`.

7. Проверь результат.

```sh
learn ps
```

```sh
curl -s https://learn.example.com/api/state
```

Оба контейнера должны быть в состоянии `running`, у `db` и `app` статус `healthy`. Запрос возвращает JSON, в котором есть `"telegram":true`.

8. Подключи приложение к боту. В BotFather: `/mybots` → бот → `Bot Settings` → `Menu Button` → укажи адрес из `PUBLIC_ORIGIN`. [Настройка кнопки меню](https://core.telegram.org/bots/webapps#launching-mini-apps-from-the-menu-button)
9. Открой бота своим аккаунтом и нажми кнопку меню. Откроется список учеников. В «Моём кабинете» виден шестизначный код.
10. Менти открывает того же бота и вводит код. Код меняется в полночь по Волгограду и нужен один раз, при первой активации. Затем менти один раз проходит входной тест.

## Вход ментора из браузера

Без этих переменных ментор входит только через Telegram. Чтобы открывать кабинет с компьютера:

1. На машине с Node.js 22 или новее дважды запусти команду в папке проекта: для пароля и для PIN из 4–8 цифр. Значение вводится с клавиатуры, команда печатает хеш.

```sh
npm run mentor:hash
```

2. Запиши в `.env` почту в `MENTOR_EMAIL` и два хеша в `MENTOR_PASSWORD_HASH` и `MENTOR_PIN_HASH`. Сам пароль и PIN в файл не попадают.
3. Примени настройки командой `learn up -d --wait`.
4. Открой адрес приложения в браузере, удерживай логотип 10 секунд, введи почту и пароль, затем PIN.

После пяти неверных попыток вход закрывается на 10 минут. Перезапуск контейнера `app` сбрасывает счётчик.

## Обновление

```sh
git pull
```

```sh
learn up -d --build --wait
```

Схема базы обновляется сама при старте приложения. Данные в томах сохраняются. Перед обновлением сделай резервную копию.

Откат на предыдущую версию: `git log --oneline` покажет коммиты, затем `git checkout <коммит>` и та же команда `up`. Схема только добавляет таблицы и колонки, поэтому старый код работает с новой базой.

## Резервная копия

Копия базы включает аккаунты, задачи, проекты, оценки и фото.

```sh
learn exec -T db pg_dump -U learn -Fc learn > learn-$(date +%F).dump
```

Восстановление заменяет текущие данные содержимым копии. Приложение на это время останавливается.

```sh
learn stop app
```

```sh
learn exec -T db pg_restore -U learn -d learn --clean --if-exists < learn-2026-11-12.dump
```

```sh
learn start app
```

Храни копии вне сервера. Вместе с копией сохрани `.env`: без `ACCESS_CODE_SECRET` изменятся коды доступа, без `POSTGRES_PASSWORD` приложение не подключится к восстановленному тому.

## Остановка

`learn down` останавливает контейнеры и сохраняет данные. `learn down -v` удаляет тома вместе с базой и сертификатами, используй только для полного сброса.

## Если что-то не работает

Логи приложения:

```sh
learn logs --tail=80 app
```

| Симптом | Причина и решение |
|---|---|
| `up` сразу падает с `Set ...` | В `.env` не заполнена названная переменная. |
| `app` перезапускается, в логе `Set PUBLIC_ORIGIN to an HTTPS origin` | `PUBLIC_ORIGIN` с путём, со слешем в конце или без `https://`, либо `TELEGRAM_MENTOR_ID` содержит не только цифры. |
| Браузер пишет об ошибке сертификата | DNS ещё не указывает на сервер, закрыты порты 80 и 443 или сертификат Nginx не выпущен. Проверь `sudo nginx -t` и журнал Nginx. |
| В Telegram «У этого аккаунта нет доступа» | Токен бота в `.env` от другого бота, либо часы сервера расходятся с реальным временем больше чем на 10 минут. |
| Ментор видит экран ученика | В `TELEGRAM_MENTOR_ID` чужой ID. Исправь значение и выполни `learn up -d --wait`. |
| «Код не подошёл» | Код вчерашний, он меняется в полночь по Волгограду. После пяти ошибок ввод закрыт на 10 минут. |
| «Сервис временно недоступен» | Приложение не достучалось до базы. Проверь `learn ps` и `learn logs db`. Частая причина — пароль в `.env` изменили после создания тома. |
| После правки `.env` ничего не поменялось | Настройки читаются при создании контейнера. Выполни `learn up -d --wait`. |

## Приветствие бота

Для ответа на `/start` задай `TELEGRAM_WEBHOOK_SECRET` отдельным значением из `openssl rand -hex 32` в окружении сервера, пересоздай `app` и зарегистрируй webhook. Выполни команду на сервере с уже загруженными переменными окружения.

```sh
curl --fail-with-body -sS -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/setWebhook" \
  --data-urlencode "url=${PUBLIC_ORIGIN}/api/telegram/webhook" \
  --data-urlencode "secret_token=${TELEGRAM_WEBHOOK_SECRET}" \
  --data-urlencode 'allowed_updates=["message"]'
```

Проверь `/start` в личном чате с ботом. Telegram поддерживает один webhook на бота. Если бот уже принимает обновления в другом сервисе, перенеси обработчик команды туда до переключения webhook.
