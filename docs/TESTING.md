# Проверки

Для прототипа запускай `npm test` и `npm run build` и проверяй [локальный сервер](http://127.0.0.1:5188/) в браузере на мобильной и широкой ширине. Для документации проверяй локальные ссылки, полноту маршрутов и актуальность журнала задач.

Первые сценарии для проверки приложения:

- создание аккаунта, верная и неверная активация по суточному коду, разделение данных учеников;
- создание задачи ментором и разрешённый и запрещённый перенос менти;
- круг на главной, свайп, кнопки, три слоя при наклоне и подписи секторов;
- профиль, слои и фотодневник до и после перезагрузки;
- все 30 вопросов, однократность прохождения, результат и отдельная правка оценки ментором;
- одинаковый список софтов и отдельный прогресс у двух менти, круг хардов из двух навыков и Lottie на пороге;
- доступные события подключённого проекта и состояние при недоступной интеграции.

## Юнит-тесты

`npm test` запускает встроенный `node --test` без PostgreSQL, браузера и новых зависимостей. Тесты лежат в [test](../test).

- `assessment.test.js` — подсчёт 30 ответов, границы 0 и 100, отказ на неполных ответах, совпадение числа вопросов с ключом.
- `input.test.js` — даты, время, диапазон задачи, текст, ссылки проекта.
- `telegram.test.js` — подпись `initData`, срок жизни, профиль, номер из контакта, суточный код и смена в полночь по Волгограду.
- `api.test.js` — маршруты на подменённой базе: роли, ожидание кода, Origin, тип тела, локальный и Telegram-вход, 404.
- `schedule.test.js` — недели, фильтры календаря, «Ближайшее», порядок вариантов теста.

Логику, которую нужно покрыть тестом, выноси из `server/api.js` и `src/app.js` в модуль без базы и DOM. SQL и транзакции юнит-тесты не проверяют, для них остаётся сценарий в браузере с настоящей PostgreSQL.

В отчёте фиксируй команду или способ проверки, результат и пробелы. Для ручных проверок используй [MANUAL-CHECKS.md](MANUAL-CHECKS.md).
